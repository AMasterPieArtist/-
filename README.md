# 自在身材 · 本地单用户 MVP

在你提供的 **「自在身材 · 交互原型 V1.1」原页面** 上接入 Python、SQLite 和 DeepSeek。沿用原配色、侧栏、页面结构与餐食图片。

**只需要 Python 3.10+。无需 Node.js、npm、数据库服务或 Python 第三方依赖。**

## 在 VS Code 中运行

1. 解压整个项目，在 VS Code 中打开包含 `app.py` 的 `zizai-local` 文件夹。
2. 打开「终端 → 新建终端」，执行：

   ```powershell
   py -3 app.py
   ```

3. 在浏览器地址栏输入 `http://127.0.0.1:8765`。

如果电脑使用 `python`，执行 `python app.py`。Windows 也可双击 `start.bat`；macOS / Linux 使用 `python3 app.py` 或 `bash start.sh`。

保持终端运行，停止时按 `Ctrl+C`。首次启动自动创建 `data/zizai.sqlite3` 和数据表。重启程序继续使用已保存的数据库。

> 不要双击 `web/index.html`，也不要用 Live Server 单独打开页面。页面必须通过 Python 服务调用数据库接口。

VS Code 安装推荐的 Python 扩展后可按 F5，选择「启动自在身材后端」。用终端启动不需要扩展。

## 先体验本地演示

右上角保持「本地演示」，依次完成三步画像，点击「保存画像，查看策略」，再生成今日计划。表单预填的是示例，填写并保存前不会自动当作你的真实画像。

- 四餐及轻量运动建议保存到 SQLite。
- A/B/C 选择、换一批、没有这些菜、不喜欢、完成状态可保存。
- 换一批只更新候选；点击「选择这个」才替换正式餐食。
- 饮品、小食、运动安排可添加／移除并持久保存。
- 动态调整支持奶茶、聚餐／火锅、加班／不想运动三个模板场景。
- **生成调整草案不会修改正式计划。点击「确认并应用调整」才更新；也可保留原计划。**
- 「调整记录」保留前后快照，刷新后仍可处理待确认草案。
- 个人策略保留饮食、运动、作息、平衡重点，修改重点同样先确认草案。

演示模式不联网，不冒充 AI。模板无法处理的自由描述会说明限制。

## 配置 DeepSeek

在 Windows PowerShell 中执行：

```powershell
Copy-Item .env.example .env
```

macOS / Linux：`cp .env.example .env`。已有 `.env` 时直接编辑，不要覆盖。

在本地 `.env` 中填写：

```dotenv
DEEPSEEK_API_KEY=在你电脑上填写真实的Key
DEEPSEEK_MODEL=deepseek-chat
```

保存后重启后端。在「偏好与限制」阅读发送字段、勾选授权并保存，再将右上角切换为「DeepSeek AI」。

Key 仅由 Python 后端读取，不进入网页、导出数据或 Git；`.env` 和数据库已被忽略。不要把真实 Key 写进 `.env.example`、发到聊天或提交仓库。调用费用由你的 DeepSeek 账号承担。

进程环境变量优先于 `.env`。上游固定为 `https://api.deepseek.com/chat/completions`，保留 TLS 验证。鉴权、额度、网络、超时和输出错误会明确提示；无效 JSON／候选最多修复重试一次。失败后保留当前计划，不偷偷返回演示数据。

## 原有页面的连接情况

| 页面 | 当前行为 |
| --- | --- |
| 欢迎、三步画像 | 基本信息、目标、场景、作息、习惯、偏好、忌口、授权保存 |
| 个人策略 | 原有重点模板；策略调整草案和确认保存 |
| 今日计划 | 四餐、完成状态、小食、运动；按日期查看 |
| 午餐推荐 | A/B/C，扩展为可切换四个餐次；采纳和换批反馈保存 |
| 动态调整 | 本地模板或 DeepSeek；前后比较、确认／放弃 |
| 饮品与小食 | 添加／移除；已知部分计入估算，品牌配方未知则标注 |
| 运动安排 | 添加／移除、状态建议、休息确认；不抵扣饮食能量 |
| 食品数据（新增） | 22 条基础食品、重量基准、参考营养、来源和标签 |
| 调整记录（新增） | 待确认、已确认、放弃和过期草案 |
| 我的数据（新增） | 授权说明、撤回、导出 JSON、删除个人数据 |

每次正式计划修改都会递增版本，旧草案失效。已完成餐次不会被自动替换。画像更新后旧计划仍可查看，但编辑前须重新生成，确保新忌口生效。重新生成会替换当天四餐、小食和运动，页面会要求明确确认。

小型候选库耗尽时明确提示，不循环假装新推荐；重新生成可开启新一轮。个人策略讨论仍用模板，自由描述 AI 能力在「动态调整」。

## 数据与规则的边界

这是可运行的产品原型，**不是经过营养专业验证的处方系统**。实现依据 PRD，但没有把其中「待确认」的内容写成已完成专业验证。

- 食品参考 USDA SR Legacy，人工转录，尚未逐条专业复核。显示每100g基准、来源、更新时间和参考状态；不代表餐厅或品牌实测数据。
- 原原型中没有依据的奶茶／蛋糕数字已替换为「待补充」，不会虚构热量。小食是用户主动选择，单独加在四餐外；未知配方显示「+ 待补充」，不宣称全天总量完整。
- Mifflin–St Jeor 公式配原型活动系数，只做**维持能量参考**，不按目标体重提供减重处方。
- 四餐规则检查参考能量、蛋白质、碳水、脂肪、蔬菜及最低能量护栏；阈值与食谱待专业复核，通过不等于营养充分或适合个人。
- 忌口按结构化标签过滤；未知限制或候选不足时停止生成。实际门店配料和交叉接触必须另行核对。
- 未成年人、孕哺期、疾病／特殊营养需求、进食困扰、过低 BMI 或明显过快目标不进入普通自动规划。关键词和模型约束不能识别所有高风险表达。
- 没有医疗诊断、多人账号、线上权限、外卖连接、完整品牌数据库或已验证的减重效果指标。

详见 [规则与数据说明](docs/规则与数据说明.md)。

## 隐私与备份

数据库留在本机，为明文文件。只有选择 AI 并授权后才会发送最小必要上下文：工作、饮食、运动、作息、偏好忌口、困难、计算后的能量参考、候选食品、当天状态、小食、运动和调整文本。不会主动发送昵称、年龄、性别、身高体重、目标体重或健康状态字段；自由文本中自行填写的信息仍会发送。

撤回授权影响后续请求，无法撤回已发到 DeepSeek 的数据。可用「我的数据」导出 JSON；完整备份请先停止程序再复制 `data` 文件夹。删除不清除导出的副本，也不保证磁盘级不可恢复。

服务只监听 `127.0.0.1`，无登录；同一电脑上的其他程序可能访问本地接口。本版不适合直接转发公网或用于多用户线上服务。

## 测试

无需额外安装即可执行，不使用个人数据库，也不真实调用付费模型：

```powershell
py -3 -m unittest discover -s tests -v
```

可选浏览器测试需 Playwright 和 Chromium，必须针对**空的临时数据库**运行，日常使用无需安装：

```text
python app.py --port 8766 --db 临时测试数据库路径.sqlite3
python tests/browser_smoke.py http://127.0.0.1:8766
```

见 [验证记录](docs/验证记录.md)。真实 DeepSeek Key 未提供，实际账号的成功调用需你填 Key 后验证。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 Python | 安装 Python 3.10+；Windows 安装时勾选 Add Python to PATH，重启 VS Code |
| 端口被占用 | `py -3 app.py --port 8766`，浏览器使用相同端口 |
| 页面连接失败 | 不用 `file://` 或 Live Server；确认 Python 终端仍在运行 |
| 改 Key 后仍未配置 | `.env` 应与 `app.py` 同级，不能叫 `.env.txt`；重启服务 |
| AI 需要授权 | 第三步勾选授权并保存 |
| 草案过期或版本冲突 | 刷新查看新计划，再生成草案，避免覆盖新选择 |
| 无法覆盖忌口 | 不删除真实过敏信息；需要补充可靠食品数据 |

```text
zizai/deepseek.py      .env、Prompt、模型调用与校验

data/                  首次启动生成数据库，不含交付测试数据

docs/                  API、需求衔接、规则和验证截图

.vscode/               VS Code 配置
start.bat / start.sh    快捷启动
```
