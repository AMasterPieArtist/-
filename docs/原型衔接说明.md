# 原型衔接说明

实际依据用户上传的 `PRD.docx`（V1.0）和 `outputs.zip` 中的 `outputs/zizai/dist/`，没有声称读取未提供的聊天上下文。

- `index.html`：品牌、侧栏、主区域和页脚保留，补充模式选择和加载状态。
- `style.css`：原浅绿配色、布局和响应式样式完整保留在文件前部，新增状态样式追加在后部。
- `app.js`：欢迎、三步画像、今日计划、餐次候选与动态调整沿用原结构，改为同源 API。
- `extras.js`：个人策略、饮品小食、运动安排保留并持久化。
- `food.jpg`：原图片字节保持一致。
- 原压缩包截图作为视觉参考，没有重新设计整套页面。

| PRD / 约定 | 本版 |
| --- | --- |
| 三步画像与生活节奏 | 实现并保存；补充目标、健康情况与授权 |
| 食堂／外卖 A/B/C | 结构化基础食谱、现实优化提示；不宣称商家实际有售 |
| 草案确认与审计 | 前后快照、事务确认、版本冲突保护 |
| 刷新、重启保留 | SQLite，经过测试 |
| DeepSeek | 后端、最小化上下文、结构验证、失败提示；Key 由用户本地填写 |
| LLM + 知识库 | 结构化过滤检索，模型只能选候选 ID，不是向量库或完整 Agent |
| 营养阈值待确认 | 可测试的原型护栏，明确待专业复核 |
| 原奶茶等假设数字 | 无可靠配方的数值不再使用，标注未知 |
| PRD 建议 Streamlit | 为保留用户现有设计，采用原 HTML/CSS/JS 配 Python 后端 |
| 行为数据 | 保存生成／失败、采纳、换批、不可得／不喜欢、完成、调整与评分；不宣称指标改善 |

后续仍需专业营养复核、品牌数据库、真实用户研究、完整曝光漏斗与评测仪表盘、账号／权限、多用户部署。没有实现视频、食物图片识别、外卖平台连接或完整 Agent。

交付包不包含真实 Key 或用户数据库。原型图片来自用户上传文件。
